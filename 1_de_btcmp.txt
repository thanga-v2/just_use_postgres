| Pattern             | Meaning                                                                       |
| ------------------- | ----------------------------------------------------------------------------- |
| `^`                 | Start of string anchor                                                        |
| `[A-Za-z0-9._%+-]+` | Username part: letters, numbers, dots, underscores, %, +, - (at least 1 char) |
| `@`                 | Literal @ symbol                                                              |
| `[A-Za-z0-9.-]+`    | Domain name: letters, numbers, dots, hyphens                                  |
| `\.`                | Literal dot (escaped with backslash)                                          |
| `[A-Za-z]{2,}`      | Top-level domain: 2+ letters (com, io, berlin)                                |
| `$`                 | End of string anchor                                                          |

German database administrators will ask you in interviews: 
"How do you handle schema migrations on tables with 10 million rows?"
The answer they're looking for: 
"I validate data first, use ALGORITHM=INPLACE (MySQL) or CONCURRENTLY (PostgreSQL) to avoid locks, and have a rollback script."

The answer you currently have: "I just ALTER and hope it doesn't break production."

///// ON DELETE RESTRICT vs ON DELETE CASCADE /////

ON DELETE RESTRICT -> Guardian

ON DELETE CASCADE  -> Automatic Cleaner



create table product (
    id SERIAL PRIMARY key,
    name text not null check (length(name) > 2),
    price NUMERIC(3,2) not null check(price > 0),
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

CREATE TABLE orders (
    order_id SERIAL PRIMARY KEY,
    user_id INTEGER NOT NULL,
    product_id INTEGER NOT NULL,
    order_quantity INTEGER NOT NULL CHECK (order_quantity > 0),
    ordered_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    

    CONSTRAINT orders_user_fk 
        FOREIGN KEY (user_id) REFERENCES users(user_id) 
        ON DELETE RESTRICT,  -- Can't delete users with orders
    
    CONSTRAINT orders_product_fk 
        FOREIGN KEY (product_id) REFERENCES product(id) 
        ON DELETE RESTRICT  -- Can't delete products with orders history
);
